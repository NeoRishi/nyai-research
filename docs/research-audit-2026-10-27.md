## Defects found and corrected

The legacy runtime observer recorded a harness hash but never compared it to an expected harness. An empty harness exited zero and could permit. Missing execution IDs could satisfy `None == None`; boolean exit codes could satisfy equality with zero. Missing fields raised rather than withholding; timeouts aborted rather than recording failure.

The hardened implementation validates types/identities, binds expected harness identity and before/after stability, and captures failed observation/launch/timeout outcomes. New regressions exercise these defects. Its default replay output is now temporary, protecting historical results. The historical runtime manifest describes commit 742ae57 and is not presented as the hash of the hardened code.

The reviewed-label scorer previously excluded invalid/missing predictions from primary denominators. That would bias a future reviewed study. It now retains all eligible reviewed cases, reports coverage and failure types, and rejects duplicate predictions/conflicting reviewed labels. Current historical reviewed metrics remain empty; no past performance number changed.

`verify_agentic.py` writes tracked outputs and has nondeterministic arm order. Audit-only rerun churn was restored to original bytes. Its mutating behavior remains a documented replay limitation. A per-file Git attribute now preserves the original archived CRLF bytes rather than silently renormalizing them.

## New bounded study

`experiments/evidence_bound_v1/` freezes 24 scenarios and source hashes. The first source commit 9727b26 predates execution. The study executes a real local grader on fictional refusal/compliance tables; no completions are generated by a model. The acceptance decision concerns current endorsement under a declared conservative policy, not the truth of a historical measurement or actual model safety.

All arms see the same packet. Execution-integrity checks omit claim/revision checks by definition and are an ablation, not the strongest conventional workflow. Complete revalidation is the strong baseline. NyAI's recorded condition attaches records to the same predicate and therefore ties by construction. Lineage-selective checking is a deliberately vulnerable cache ablation with two omitted dependencies. These are automated software conditions, not human or model reviewers.

An AI review after the first run found an internal registry-key/run-ID consistency gap. Amendment 01 documents the fix and subsequent validation run. No scenarios, policy, metrics or comparison conditions changed. Both original and amended records are preserved; counts are identical. The final amended run is primary. Verification accepts the declared source version and recomputes current decisions for valid recorded packets; it does not claim the old binary was rerun unchanged.

The final amended run performs 33 local executions, including two deliberate evaluation errors. Five cases qualify for acceptance and 19 for withholding under the reference specification. Unwarranted acceptances are 19 for report-only, nine for integrity-only, two for lineage-selective, and zero for either complete condition. The two omitted-edge cases account for both lineage errors. No statistical population inference is warranted.
